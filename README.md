## What is CELLO?

CELLO is an open source benchmark for evaluating LLM code transpilation quality. It evaluates **C → Rust** transpilation using **real rustc compilation** and scores across 6 quality dimensions.

### Key Features

| Feature | CELLO |
|---------|-------|
| Real Compilation | ✅ Uses rustc to verify generated code |
| Transparent Methodology | ✅ Fully open — all prompts, configs, and scripts public |
| Detailed Reports | ✅ C source, Rust output, errors, and scoring breakdowns |
| Reproducible | ✅ All evaluation code available |
| Community Contributions | ✅ Open for PRs |
| License | Apache 2.0 |

| hashmap | 3,297 bytes | Hash map with separate chaining |

## Evaluation Dimensions

1. **Compilation (25%)** — Does it compile with rustc?
2. **Safety (20%)** — Memory safety improvements (unsafe blocks, error handling)
3. **Quality (20%)** — Idiomatic Rust patterns, documentation, naming
4. **Correctness (15%)** — Functional equivalence, edge cases, tests
5. **Maintainability (10%)** — Code organization, public API clarity
6. **Performance (10%)** — Efficiency patterns (minimal cloning, references)

## Quick Start

**View the website:**
```
https://aosf-org.github.io/cello/
```

**Reproduce evaluations:**
```bash
# Install Rust
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# Install dependencies
cd evaluations && pip install -r requirements.txt

# Configure API keys
cp .env.example .env
# Edit .env with your keys

# Run evaluation
python run_evaluation.py --all
```

📖 See [QUICKSTART.md](QUICKSTART.md) for detailed setup  
📖 See [EVALUATION.md](EVALUATION.md) for complete evaluation guide

## Scalable Framework

CELLO uses a **config-driven architecture** for easy expansion:

### Add a New Model

Just edit `config/models.yaml` (no code changes):

```yaml
gpt-4o:
  name: "GPT-4o"
  provider: openai
  model_id: "gpt-4o"
  api_key_env: "OPENAI_API_KEY"
  enabled: true
```

### Add a New Project

1. Add C file to `test-projects/c/`
2. Add entry to `config/projects.yaml`

That's it! The framework handles the rest.

## Deploy to GitHub Pages

### Option 1: Direct deployment

1. Fork or clone this repository
2. Go to **Settings → Pages**
3. Set source to **Deploy from a branch**
4. Select `main` branch, `/ (root)` folder
5. Click **Save**

Your site will be live at `https://<username>.github.io/<repo-name>/`

### Option 2: Quick manual deploy

```bash
# Clone and push to your own repo
git clone https://github.com/cello-benchmark/cello.git
cd cello
git remote set-url origin https://github.com/<your-username>/<your-repo>.git
git push -u origin main
```

Then enable GitHub Pages in Settings.

### Option 3: Local preview

```bash
# Using Python
python3 -m http.server 8000

# Using Node.js
npx serve .
```

Open `http://localhost:8000` in your browser.

## Project Structure

```
cello/
├── README.md                    # This file
├── QUICKSTART.md                # 5-minute setup guide
├── EVALUATION.md                # Detailed evaluation guide
├── index.html                   # Main leaderboard website
├── .gitignore                   # Excludes .env and build artifacts
│
├── config/                      # Configuration files (edit to customize)
│   ├── models.yaml              # Model definitions
│   ├── projects.yaml            # Test projects catalog

│
├── evaluations/                 # Evaluation framework

│   │   ├── config_loader.py    # YAML config loader

│   │   ├── base_provider.py    # Abstract interface
│   │   ├── anthropic_provider.py
│   │   ├── google_provider.py
│   │   └── ...

│   ├── requirements.txt         # Python dependencies
│   └── .env.example             # API key template (NO REAL KEYS)
│
├── test-projects/               # Test code
│   └── c/                       # C source files
│       ├── string_utils.c
│       ├── buffer.c
│       └── hashmap.c
│
├── results/                     # Evaluation results (JSON)
│   └── 2026-02-16-poc/          # Example POC run
```
